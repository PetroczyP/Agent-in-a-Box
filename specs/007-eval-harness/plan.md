# Implementation Plan: Eval Harness (007)

**Branch**: `007-eval-harness` | **Date**: 2026-03-31 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/007-eval-harness/spec.md`

## Summary

Build a standalone eval harness (`eval/` at repo root) that measures AgentinaBox reviewer quality against curated golden test cases. The harness is a CLI tool (`python -m eval`) that connects to a live reviewer via MCP stdio transport (docker exec), runs golden cases through `start_review`/`discuss`/`get_review_summary`, grades findings via a two-tier pipeline (deterministic fingerprint + model-based semantic grading), computes precision/recall/SNR/severity accuracy/category accuracy with SEM statistical reporting, and outputs markdown + JSON scorecards. Supports CI mode (`--ci`) with threshold-based pass/fail.

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: `mcp>=1.0.0` (MCP client SDK), `anthropic>=0.86.0` (Tier 2 grader), `pydantic>=2.12` (models)
**Storage**: File-based (golden cases in `eval/fixtures/`, results in `eval/results/`). No database.
**Testing**: pytest (`tests/test_eval/`)
**Target Platform**: Host machine (macOS/Linux), communicates with reviewer in Docker container
**Project Type**: CLI tool (standalone eval harness, not part of the review server)
**Performance Goals**: Full eval suite (20+ cases × 3 trials) completes in <30 minutes (SC-001)
**Constraints**: No container filesystem access (all context via MCP). Anthropic API key stays on host only.
**Scale/Scope**: 20+ golden cases, 3 trials per case, ~60 review sessions per run

## Constitution Check

| I. Project-Agnostic | PASS | Eval harness tests the reviewer's generic capability, not tied to any specific repo. Golden cases are synthetic/curated. |
| II. Context via MCP | PASS | All review context sent via MCP `start_review` parameters. No volume mounts. |
| III. Security Boundary | PASS | Anthropic API key stays on host (Tier 2 grader runs on host). GitHub PAT in container only for Copilot. |
| IV. Test-First | PASS | TDD applies to eval harness code itself. Tests in `tests/test_eval/`. |
| V. Model-Agnostic | PASS | Eval harness tests whatever model the reviewer is configured to use. Grader model is independent and configurable. |
| VI. Simplicity | PASS | CLI tool with argparse, file-based fixtures, no database, no web UI. Markdown + JSON output. |
