# Feature Specification: AgentinaBox — REST API Transport

**Feature Branch**: `011-rest-api`
**Created**: 2026-03-16
**Status**: Backlog (Draft)
**Depends on**: 001-ai-code-reviewer

## Summary

Expose AgentinaBox's review capabilities via a standard REST API (HTTP/JSON) alongside the existing MCP transport. This enables integration with systems that cannot or choose not to use MCP — CI/CD pipelines, GitHub Actions, GitLab CI, Jenkins, custom tooling, and enterprises that restrict MCP usage.

## Motivation

MCP is a relatively new protocol (2024). Many enterprises have not yet evaluated or approved it. CI/CD pipelines typically integrate via HTTP webhooks and REST APIs, not MCP stdio. Offering a REST API makes AgentinaBox a drop-in component for any system that can make HTTP calls.

The review engine is already decoupled from the MCP transport layer — `server/mcp_server.py` is a thin wrapper around `server/review_engine.py`. Adding a REST API means creating a second thin wrapper over the same engine.

## Open Questions

- Should the REST API live on the same port as the web dashboard (8080) or a separate port?
- Do we need API key authentication for the REST endpoints, or is network-level isolation (Docker networking) sufficient?
- Should we support webhooks (AgentinaBox calls back when review is done) for async CI/CD integration?
- What's the response format — raw Finding JSON, or full SARIF?
- Do we need OpenAPI/Swagger documentation auto-generated by FastAPI?

## Rough User Stories

### US1 - Submit Review via REST API (P1)

A CI/CD pipeline sends a `POST /api/v1/reviews` request with the code bundle (diff, files, conventions) as JSON. The server processes the review and returns structured findings in the response body.

```
POST /api/v1/reviews
Content-Type: application/json

{
  "diff": "...",
  "files": [...],
  "conventions": "..."
}

→ 200 OK
{
  "session_id": "...",
  "findings": [...]
}
```

### US2 - Discuss via REST API (P2)

A system sends a `POST /api/v1/reviews/{session_id}/discuss` request to follow up on findings. Works identically to the MCP `discuss` tool but over HTTP.

### US3 - GitHub Actions Integration (P2)

A GitHub Action calls the AgentinaBox REST API on every PR, posts findings as PR review comments. The Action is a thin HTTP client — all intelligence lives in the container.

### US4 - GitLab CI / Jenkins Integration (P3)

Same pattern as GitHub Actions but for GitLab CI and Jenkins pipelines. The REST API is CI-system agnostic.

## Architecture Note

```
MCP clients (Claude Code, etc.)  ──stdio──▶  mcp_server.py  ──▶  review_engine.py
CI/CD pipelines, custom tools    ──HTTP───▶  rest_api.py    ──▶  review_engine.py
Web dashboard                    ──HTTP───▶  web_routes.py  ──▶  review_engine.py
```

All three transport layers share the same review engine. No duplication of business logic.

## Technical Notes

- FastAPI already powers the web dashboard — adding REST routes is trivial
- FastAPI auto-generates OpenAPI/Swagger docs at `/docs`
- Consider rate limiting for public-facing deployments
- Async endpoint support for long-running reviews (return 202 + poll, or webhook callback)
